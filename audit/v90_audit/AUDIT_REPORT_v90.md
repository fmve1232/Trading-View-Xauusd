## Report 1: Executive summary

**Overall condition: functional, internally consistent, and well instrumented. Not statistically validated.**

The code does what it says in nearly every place I could test. Its central weaknesses are evidential and
presentational, not arithmetic.

| Dimension | Assessment | Basis |
|---|---|---|
| Mathematical reliability | **Good** | Every formula recalculated independently matched (Kelly, Wilson, t quantile, cost in R, plan expectancy, NY day boundary, DST, evidence weights). One genuinely dead term (B-08). |
| Engine reliability | **Good, with caveats** | No look-ahead found. The higher-timeframe requests are the documented non-repainting pattern. The risk lock depends on loaded history on 5m / 1m (B-09). |
| Strategy reliability | **Unknown** | On the registered 15m timeframe the four Pine strategies have 1 / 0 / 1 / 1 closed positions. No edge is shown either way. The only decisive record (website arm H4) is negative. |
| Probability / statistics | **Weak** | The calibrated score is correctly built (grouped-logit WLS, Wilson-shrunk Kelly) but has **no measured skill** out of sample (F-A78: AUC 0.48–0.53, negative Brier skill). It is correctly labelled "score". |
| Execution and risk | **Fair** | Costs are consistent between the model and the strategy files and are not double counted. But the Master's lot size omits cost (B-01, risk 8–24% over the ceiling), two lot sizes appear on the chart (B-02), and there is no news-time cost or default news block (B-03). |
| Pine engineering | **Good statically; compile unverified** | 0 static issues, 0 dead values (with the companion rule), 26 checkers. **TradingView compile of v86–v90: NOT RUN.** The Master has under ~80 tokens of headroom. |
| Dashboard | **Accurate but easy to over-read** | Values trace to their engines (Visuals' MACRO is the Master's, verbatim). Many prominent items cannot change a BUY / SELL (B-14). |
| Checkers | **Strong but not a proof** | Executed-Pine checkers are genuine. Several "passes" are frozen-text tripwires. `bug_scan` never fails (C-02). Mutation results: Report 10. |

**Production readiness:**

- As a **manual decision-support display**: usable, once B-01 / B-02 / B-03 are understood.
- As a **probability-driven or automated** system: **not ready**. No arm has shown an edge, the probability has no
  skill, and v86–v90 have not been compiled.

**Strengths:**

- the pre-registration discipline;
- byte-parity between the engine copies;
- execution of the Pine text against references;
- non-repainting higher-timeframe data;
- honest labels ("score", "display only", measured AUC on screen).

**Critical weakness:** the system has no demonstrated predictive edge. No code change can fix that; only a frozen
forward record can (§9 of the audit prompt).

## Report 6: Probability and statistics audit

| Item | Status |
|---|---|
| Score → calibrated P (`_calP`, L4593) | Correctly built: logistic of the WLS fit, slope clamped, fitted online on resolved outcomes only (no look-ahead). **Mathematically correct; statistically not validated.** F-A78: AUC 0.484 (15m) / 0.515 (1h), Brier skill −0.056 / −0.042, measured on the website port. `pine_web_parity`: same event, normalisation and interpolation. |

| Out-of-sample analog win rates | "Rolling, not a holdout" (F-037B, documented). Not a validated probability. |

Per-trade R with N < 50 gives no stable estimate, and ratios on 1–8 trades would be invented precision. |
| Presentation | "score", not %, and the SCORE row shows the measured AUC. **No probability is presented as a win rate.** |
