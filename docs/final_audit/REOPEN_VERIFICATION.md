# Weekend-reopening verification (mandate 28 Nov 2026, Part 2)

**Status of the Part 2 verification: PENDING.**

- The first production run on the G4 code is the first one after the 29 Nov reopening (23:00 UTC).
- Part 2 is reported only from records written by those runs.

## The tool

Read-only, `audit/tools/reopen_check.py`:

| Check | What it verifies |
|---|---|
| R1 | The first valid bar opens at 18:00 New York |
| R2 | The stale Friday quote (the feed's first print) is replaced as the engine does |
| R2b | The first bar does not reach beyond Friday's close against the gap. If it does, the bar is flagged **SUSPECT**, with the ledger exits and G4 records it decides |
| R3 | No shut-window bar survives cleaning |
| R4 | Ordering and the 5-minute grid |
| R5 | Consistency with COMEX GC=F futures, premium removed. Tolerance: the 95th percentile of the last session before the break. Futures, not spot |
| R6 | No record read an unclosed (still-forming) bar |
| R7 | The entry-bar and next-bar conventions |
| R8 | Independent recomputation of every record by `audit/tools/trade_diag_check.py` |
| R9 | Expected and actual record counts; duplicates, missing records, conflicting copies, changed ledger trades |

`audit/tools/protected_check.py` checks the freeze key, the seven Pine hashes (manifest and pre-registration) and the store's freeze key. It runs before and after every change.

**Spot cross-check: unavailable.** An independent spot tick source is not reachable from the cloud session: `datafeed.dukascopy.com` is refused by the environment's network policy, and Dukascopy also refuses GitHub's runners. R5 therefore compares with futures.

**What the dry run found** (the numbers above are generated from the evidence file):

- **The stale open is fixed; the stale low is not.** The engine's repair of the first bar (`sources.repair_reopen`) replaces the stale open, but it keeps the bar's low.
  - On 22 Nov that low lies far below Friday's close, on a reopening that gapped up.
  - Without a tick source it cannot be verified. It is very unlikely to be a trade.
- **It decided one engine exit.** The frozen engine's forward ledger holds one exit inside that range: a stop at the reopening, when gold had gapped up.
- **It changed G4 records.** Some G4 records change when the low is replaced by the nearer of the bar's open and the next bar's open.
- **No change made.** `sources.repair_reopen` is one of the frozen engine sources (`holdout.ENGINE_SOURCES`). Changing it would restart the forward test, so it needs an amendment and the operator's approval. This finding is reported, not fixed. G4 records stay as written.
